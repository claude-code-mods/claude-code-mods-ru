TavernWeaveX 无限月读 (сокращенно TW) помогает превратить ваши идеи в рабочие карты персонажей, веб-страницы и утилиты, которые можно дорабатывать. Вы просто говорите, что хотите сделать или где что-то не так; TW уточняет требования, предлагает решение, изготавливает и проверяет результат, а затем объясняет, как его опробовать. Работа организуется через навыки (Skill), загружаемые по задаче; поддерживаются Codex, Claude Code и DeepSeek Harness через пакет **TavernWeave X DSH**, в который входит панель клиента «Божественная рука».

Текущий исходный код — **официальный выпуск TavernWeaveX 无限月读 2.4.0**: нативная адаптация Antigravity (AGY), сохранение четырех уровней предпочтений по настройке и исправление согласованности версий между хостами; всего 23 нативных навыка, названия и количество не изменились. Плагин Claude Code из 2.2.0 по-прежнему обеспечивает автоматическую инъекцию Host Front Door, агента `tavernweave` и переключатель Soul (см. [Плагин Claude Code](#плагин-claude-code)); пакет **TavernWeave X DSH** содержит панель «Божественная рука», доступны проектирование и написание world book. Идентификатор установки `tavernweave-agent-skills`, имена навыков и адреса репозитория сохраняются, чтобы можно было проверить обновление. Полный пакет и файлы проверок — на [странице v2.4.0](https://github.com/LiarMTTT/TavernWeave/releases/tag/v2.4.0); архив выпусков [v2.2.0](https://github.com/LiarMTTT/TavernWeave/releases/tag/v2.2.0), [v2.1.0](https://github.com/LiarMTTT/TavernWeave/releases/tag/v2.1.0), [v1.9.1](https://github.com/LiarMTTT/TavernWeave/releases/tag/v1.9.1) и [v1.9.0](https://github.com/LiarMTTT/TavernWeave/releases/tag/v1.9.0) сохраняется.

**Основное назначение единого плагина — позволить авторизованным пользователям вызывать TW при долгих задачах в облаке dots.** Codex и dots используют один архив `TavernWeave-Codex-v2.4.0.zip`, отдельной cloud-версии нет. TW предоставляет навыки и справочные материалы; выполнение, продолжение, постоянное хранилище и инструменты исходят от самого хоста. Локальная установка не синхронизируется с аккаунтом dots автоматически. Способ использования и вход в аккаунт описаны в **[руководстве по единому плагину](docs/plugin-guide.md)**.

TW может отдельно проектировать или переписывать world book: сначала уточняются границы знаний, текст и условия срабатывания, затем выбирается вариант — нативные записи, условный вывод, явное чтение или частичный гибридный подход. За содержание world book отвечает отдельный навык; работа со всей картой, построение мира, переменные и отладка выполнения передаются профильным возможностям. Оптимизация бюджета требует фактических измерений, а качество модели — наблюдения в конкретном хосте. Обычные программные задачи и работа с картами тоже используют более ясное уточнение требований и спецификацию подсказок; уже принятые решения можно переиспользовать.

Сохраняется проверенный в 1.9.0 метод творчества «Моюэ»: в основе полной карты — начальная реплика и world book, структурированные как чистый текст, MVU Zod или hybrid, с дополнениями по миру, переменным и персонажам. Для интерфейса сначала изучаются требования и релевантный дизайн; по умолчанию используется стандарт Awwwards. Интерфейс остается чистым, а текст по назначению избегает штампов.

Если вам нужно всего одно правило для подсказки карточки, тоже можно прямо попросить об этом. Агент сохранит смысл и силу ограничений и выдаст либо текст, либо запись world book. При ошибке типа `bindings` инструмент привязки полей возвращает явную диагностику, а не выбрасывает исключение метода массива. В 1.9.0 исправлена ситуация, когда на Windows после неудачного экспорта компонента оставался недоделанный файл; файлы, которые нельзя очистить, перечисляются явно. Изменения версий — в [журнале обновлений](CHANGELOG.md).

Доска прогресса проекта по-прежнему создается навыком `orchestrate-project-blueprint` внутри каждого проекта: показывает общий и модульный прогресс реализации/приемки, раскрывает контрольные точки и доказательства, сохраняет идеи, баги и дословные замечания проверяющих. Доска читает границы и критерии приемки из общего проекта, текущее состояние, доказательства и следующий этап из NEXT; синхронизация сначала показывает расхождения, а при изменении источников, обратной связи или доказательств проводит сверку заново. Новые идеи автоматически не расширяют подтвержденный объем, а проценты не заменяют решение водителя или реальную приемку в хосте. Способ использования — в [доске прогресса проекта](docs/project-progress-board.md).

Библиотека работ по-прежнему поддерживает романы, исходные и фанфикшн-материалы, сетевые текстовые и графические референсы; по умолчанию результатом становится редактируемый Markdown＋индекс JSONL с экспортом в SQLite; поиск по источнику, версии адаптации и стадии осведомленности. См. [инструкцию по библиотеке работ](docs/work-library.md).

Все возможности по-прежнему соблюдают правило простых слов и объяснения терминов; уровень — новичок, начинающий, уверенный, эксперт — выбирает пользователь. Сохраняются текстовская правка, полная и архитектурная проверка, мозговой штурм, встроенная библиотека дизайна, Soul и помощь при переходе на старую карту. Проверка установки опирается на фактически полученный манифест машины; реальная загрузка в клиенте, качество конкретного произведения и измерение токенов остаются отдельными проверками.

## Начните с одной фразы

Обычная работа с картой или Vibe Code:

```text
Я хочу использовать TavernWeave, чтобы сделать【опишите желаемый результат】.
Сначала посмотри существующие файлы и собери что-то, что можно попробовать вручную; простыми словами объясни, почему ты рекомендуешь именно это и что мне нужно решить.
```

Если файл карты уже есть, начните так:

```text
Я взял эту карту персонажа и хочу【продолжить по исходнику / сделать фанфикшн】.
Сначала помоги мне разобраться в исходной карте: какие материалы есть, что нужно сохранить, а затем вместе выберем первую правку.
```

## Работа в выбранном темпе

| Уровень поддержки | Что вы получаете |
| --- | --- |
| Новичок | По одному маленькому шагу, с подробным объяснением, где нажать, почему, терминов и ожидаемого результата |
| Начинающий | По одному небольшому этапу, также подробно объясняются способ, связь шагов, компромиссы и проверка |
| Уверенный | Обычные шаги объединяются, сообщаются ключевые решения, причины и результаты проверки |
| Эксперт | В повседневной работе сразу вывод, правки, различия и доказательства, меньше повторной базы |

Можно прямо сказать «дальше используй уровень начинающего» или «смени мой уровень на эксперта». Перед сохранением сообщается фактическое местоположение и границы, уже выбранный уровень сохраняется при обновлении; без выбора уровень не назначается автоматически. «На этот раз короче» влияет только на текущее объяснение. **На всех уровнях при необходимости или при исправлении бага объяснения остаются подробными, если вы явно не сказали, что это не нужно.**

Необходимые термины объясняются при первом появлении с сопоставлением «исходный термин / простыми словами / конкретный смысл» для текущей задачи. Простые слова и уровень независимы от личности Soul и текстовой правки; выход из одного режима не сбрасывает ваш выбор. Правила и полные примеры — в [общей коммуникации и поддержке](skills/consult-tavernweave-library/references/communication-and-guidance.md).

## Дополнительные варианты выражения и взаимодействия

Мягкое наставление:

```text
Атун，помоги мне!
```

Строгий режим обучения:

```text
MTTT.sir,拷打我！
```

Пасхалка проверки интерфейса:

```text
Душеубийца!
```

Свести одну просьбу к общему проекту и первой версии:

```text
Режим мозгового штурма
```

Позволить трем ракурсам Soul участвовать в мозговом штурме:

```text
Режим мозгового штурма, совместное заседание Soul
```

После подтверждения дизайна выполнить замороженную первую версию:

```text
Запустить первую версию по чертежу
```

Заново проверить полный путь роста Vibe Code по текущим доказательствам:

```text
Зеркало
```

Выдать только полную текстовую форму оценки, которую можно скопировать и сохранить:

```text
Зеркало: только текстовая форма оценки, без доски
```

Выйти из слоя личности:

```text
Soul на место
```

Soul является временным Portable-слоем уровня задачи. Атун и MTTT.sir — две учебные проекции публичного метода MTTT; Душеубийца проверяет интерфейс неофициальной личностью фанатского Джони Силверханда, может грубить, но обязан приводить доказательства и способ исправления. Три места — это три помеченных ракурса одного Agent с общими фактами, правами, приоритетом 1–2 необходимых решений за раунд (всего не более 4) и одним журналом сведения, а не три независимые модели. Он не получает автоматически историю ChatGPT или приватный RAG, не сохраняется навсегда между новыми задачами и не расширяет права на файлы, Git, сеть, публикацию или production.

## Правка текста и полная／архитектурная проверка · v1.4.0

Фразы «перепиши этот абзац», «убери дух ИИ», «убери канцелярит» дают отредактированный вариант с сохранением смысла. По умолчанию — легкая правка, можно задать структурную переработку или глубокий пересмотр; ролевые установки, числа, код, макросы и переменные сохраняют исходные ограничения.

| Применение | Включить | Выключить |
| --- | --- | --- |
| Однократно | перепиши этот абзац… | заканчивается после сдачи |
| В течение текущей задачи | включить режим постоянной правки | выйти из режима правки |
| Постоянно в рабочей папке | включить режим правки в этой рабочей папке | выключить режим правки в рабочей папке |
| Постоянно в клиенте | включить режим правки глобально для текущего клиента | выключить глобальный режим правки клиента |

Постоянный режим распространяется на творческий текст, внешние тексты, повседневные объяснения, планы и отчеты по проверке; цитаты, код, обязательные шаблоны и доказательства сохраняются. Постоянный режим сначала показывает фактические файлы правил и различия, а запись в отдельный блок происходит только после согласия водителя. Установка/обновление TW не включает его автоматически. Выход из задачи влияет только на текущую задачу; «посмотреть состояние режима правки» различает области и доказательства загрузки в хосте.

«Полная проверка» просматривает всю согласованную область; «архитектурная проверка» отслеживает обязанности, зависимости, состояние и ключевые цепочки; «полная архитектурная проверка» объединяет оба подхода. Подходит и для ПО, и для карточек. В отчете сохраняются проверенные, частично проверенные, непрочитанные и исключенные элементы, а также все подтвержденные находки. Можно сказать «Душеубийца, полная архитектурная проверка» в стиле Soul; краткое резюме — не более трех пунктов, полный отчет не обрезается. Проверка сначала выдает результат только для чтения.

## Пятислойный вход

```text
Host Front Door (необязательный локальный вход)
  -> Soul (Атун / MTTT.sir / Душеубийца / три места, необязательно)
    -> Оркестрация мозгового штурма (общий проект + First Playable + чертежи/набор чертежей, необязательно)
      -> Library (A0 + руководства ST + дизайн/анимация + Wiki источников + страница выбора)
        -> Инженерные навыки, распределенные по машинному манифесту (создание, компоненты, API, UI, отладка, проверка роста, сборка, приемка и др.)
```

- **Host Front Door (необязательный локальный вход)** подключает к локальному клиенту простые слова, маршрутизацию задач и правила взаимодействия; при установке плагина Claude Code инъекция выполняется хуком SessionStart автоматически, при этом используется либо он, либо блок в `CLAUDE.md` (см. [Плагин Claude Code](#плагин-claude-code)). Уровень пользователя хранится отдельно и сохраняется при обновлении входа; совпадение файлов и фактическая загрузка в клиенте проверяются раздельно.
- **Soul (необязательная личность)** меняет тон и способ обучения в пределах выбранного пользователем уровня поддержки, не изменяя факты, права и результаты приемки.
- **Оркестрация мозгового штурма** задает число раундов, решения в четырех состояниях, границы первой версии и объем чертежей; любой активный шаг не может без оснований рекурсивно размножаться. Реальную проблему можно временно разбить, но после устранения или подтверждения блокировки ветку нужно закрыть и вернуться к родительскому шагу.
- **Library** распространяется отдельными модулями и читается по требованию; однократная установка не означает, что вся библиотека загружается каждый раунд.
- **Инженерные Skill** по-прежнему выполняют реальную работу. Ни личность, ни материалы не заменяют авторитет целевой среды выполнения.

## Создание, продолжение и приемка

Долгие проекты поддерживают единый творческий авторитет через Markdown + YAML front matter + ограниченные структурные блоки. Подтвержденное, кандидаты, ожидающие решения, отклоненное, реализованное, автоматические доказательства, реальные доказательства хоста и приемка водителем не смешиваются. Когда пользователь говорит «продолжи», сначала восстанавливаются авторитет, Git/рабочее дерево, артефакты и следующий этап; к замороженным настройкам не возвращаются повторно.

Доказательства фиксируются по уровням:

```text
Исходный код -> автоматические тесты -> офлайн-артефакты -> браузер/десктоп -> реальный SillyTavern -> ручная приемка -> разрешение на выпуск
```

Ни один уровень не может выдавать себя за следующий; автоматизация никогда не может сама записать `driver-accepted`.

## Установка и обновление

Пользователям Codex сначала стоит посмотреть [особенности использования и установки для Codex](docs/codex-skills.md): там различаются расположение плагина и отдельных навыков и описан Python-вход для установки/проверки без PowerShell (по умолчанию только чтение и предпросмотр, запись — после явного применения).

Следующие шаги описывают **локальную установку** для Codex или Claude Code. Включение и использование плагина в аккаунте dots описаны в [руководстве по единому плагину](docs/plugin-guide.md); локальная установка не синхронизируется с облаком автоматически. Установщик обязан использовать как источник полный манифест `skills/` репозитория, создавать отсутствующие папки и не перезаписывать только уже существующие на машине навыки. Host Front Door — необязательное локальное улучшение; перед установкой посмотрите целевые файлы правил и различия:

```text
Установите и включите этот репозиторий навыков полностью:
https://github.com/LiarMTTT/TavernWeave

Не перезаписывайте только уже существующие на машине навыки. Ориентируйтесь на полный каталог репозитория skills/; после установки сверьте полное количество по машинному манифесту (2.3.0 — 23/23, выпущенная версия 1.9.1 — 22/22) и отдельно подтвердите наличие worldbook-design-and-writing, build-work-library, activate-tavernweave-soul, consult-tavernweave-library, orchestrate-project-blueprint, reflect-on-vibe-code-growth, rewrite-natural-prose и офлайн-страницы выбора Library.

Определите, использую ли я Codex или Claude Code; объясните, что TavernWeave Host Front Door — необязательное локальное улучшение; сначала покажите целевой путь, управляемый блок и diff, и только после моего подтверждения устанавливайте. Не переписывайте пользовательские правила вне управляемых блоков.
```

Обновление:

```text
Обновите полностью установленный TavernWeave до последней версии этого репозитория:
https://github.com/LiarMTTT/TavernWeave

Обновление должно сравнивать «какие папки должны быть в репозитории» с «фактически установленными папками», создавать новые навыки, а не только менять старые; также проверьте, не отсутствует ли, не устарел ли или не изменился ли Host Front Door, и явно предложите три варианта: «обновить front door», «сначала посмотреть diff», «обновить только навыки». После завершения верните две квитанции, затем создайте новую задачу для проверки обнаружения локальным хостом. Импорт в аккаунт dots проверяйте отдельно по руководству плагина.
```

Если хост или агент использует переносную установку «скопировать каждый навык в папку проекта», в корне репозитория выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-tavernweave.ps1 -TargetSkillRoot '<фактический корень навыков>'
```

Чтобы обработать глобальный front door при установке, явно выберите хост и позвольте сценарию спрашивать:

```powershell
# Codex: по умолчанию $CODEX_HOME\AGENTS.md; если не задано — ~/.codex/AGENTS.md
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-tavernweave.ps1 -TargetSkillRoot '<фактический корень навыков>' -AgentHost Codex -HostFrontDoorAction Prompt

# Claude Code: по умолчанию ~/.claude/CLAUDE.md
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\install-tavernweave.ps1 -TargetSkillRoot '<фактический корень навыков>' -AgentHost Claude -HostFrontDoorAction Prompt
```

Установка поддерживает только блок комментариев `tavernweave-host-front-door` с версией; для существующих файлов сначала создается резервная копия, повторная установка идемпотентна, ошибочные/повторяющиеся метки и пути ссылок отклоняются. Для отдельного предпросмотра или установки:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\manage-host-front-door.ps1 -AgentHost Codex -Action Preview
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\manage-host-front-door.ps1 -AgentHost Codex -Action Install
```

Изменение глобальных правил — отдельный этап с подтверждением; агент не должен тихо записывать их из-за слова «рекомендуется». Codex/Claude должны создать новую задачу или перезапуститься для повторного обнаружения; квитанция о front door не означает, что навык Soul действительно вызван.

После установки или обновления проверку нужно выполнять для **фактических путей поиска**, а не только для исходного репозитория. Проверяющий по умолчанию отказывается считать исходную папку TavernWeave целью установки:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify-install.ps1 -TargetRoot '<фактический корень плагина или навыков>'
```

Число навыков в квитанции должно совпадать с манифестом установки используемых исходников. Ниже пример на 23 навыках версии 2.3.0; в выпущенном исходном пакете 1.9.1 по-прежнему 22/22:

```text
INSTALLATION VERIFIED: 23/23
Library: present-and-matched
Library picker: present
Soul: present-and-matched
Host rediscovery: required-new-task
```

Если при проверке одновременно заданы хост и файл правил, квитанция также показывает `Host Front Door: current|missing-block|outdated|drifted`; это рекомендательное состояние, не влияющее на проверку целостности файлов навыков по машинному манифесту.

Посторонние личные навыки в целевой папке сохраняются; официальные папки TavernWeave из машинного манифеста должны посе файлу совпадать с текущими исходниками. Последний уровень пути записи должен называться именно `skills`; сценарий установки отклоняет корни дисков, корень домашней папки, внутренние папки исходного репозитория и символические ссылки, а при неудачной замене откатывает уже установленные официальные навыки.

После полной проверки соответствующей версии создайте новую задачу или перезапустите сеанс, чтобы локальный хост заново обнаружил навыки. В новой задаче все равно нужно реально вызвать проектирование и написание world book, Soul, оркестрацию штурма, «Зеркало» и Library; квитанция об установке не заменяет обнаружение хостом. Пакет v2.4.0, `TavernWeave-DSH-v2.4.0.tgz` (DeepSeek Harness) и файлы SHA-256 — на [странице официального выпуска](https://github.com/LiarMTTT/TavernWeave/releases/tag/v2.4.0).

Поддерживающие могут явно использовать `-AllowSourceTree` для самопроверки дерева исходников перед выпуском; этот ключ нельзя использовать для обычной квитанции пользовательской установки.

## Плагин Claude Code

Начиная с 2.2.0 сам репозиторий является маркетплейсом плагинов Claude Code (`.claude-plugin/`). В Claude Code выполните:

```text
/plugin marketplace add LiarMTTT/TavernWeave
/plugin install tavernweave-agent-skills@tavernweave
```

Плагин состоит из четырех частей; первые три полностью соответствуют пакету DSH:

| Состав | Файлы | Соответствие DSH |
| --- | --- | --- |
| 23 навыка с префиксом `tavernweave-agent-skills:` | `skills/` | Поставщик навыков |
| Автоматическая инъекция Host Front Door: при каждом начале сеанса front door добавляется в контекст (нужен `node` в PATH) | [`hooks/hooks.json`](hooks/hooks.json), [`hooks/session-start-front-door.mjs`](hooks/session-start-front-door.mjs) | Раздел system prompt |
| Агент `tavernweave`: персонаж TW с ограниченным набором инструментов (без сети и субагентов) | [`agents/tavernweave.md`](agents/tavernweave.md) | Пресет `TavernWeave X DSH` |
| Переключатель режима Soul: строка `Soul Атун ▸` над полем ввода; при раскрытии нужная инструкция просто подставляется в поле, и вы отправляете ее сами | [`hooks/soul-switch.tsx`](hooks/soul-switch.tsx) (`modules` в `hooks/hooks.json`) | Маленькое всплывающее окно Soul «Божественной руки» (в CC сохранен только этот интерфейс) |

Агент `tavernweave` можно запустить как основной сеанс: `claude --agent tavernweave-agent-skills:tavernweave`; также можно в обычном сеансе поручить Claude передать задачи TW ему. Если вы ранее скопировали навыки в `~/.claude/skills`, после перехода на плагин эту копию можно удалить, чтобы не было двух навыков с одинаковыми именами.

Переключатель Soul использует интерфейс function hook плагинов Claude Code (официально помечен как early access). Он записан в том же `hooks/hooks.json`, что и hook front door; на Claude Code 2.1.299 подтверждена загрузка обоих; для более ранних версий игнорирование поля `modules` не проверялось. Переключатель фиксирует только фактически отправленные вами инструкции Soul и не означает, что Soul подтвержденно активирован; он никогда не отправляет сообщения за вас. Тест интерфейса запускается командой `claude plugin test .`.

### Устранение дублирования с блоком CLAUDE.md

Front door нужен в одном месте. При запуске hook проверяет файлы инструкций, которые загрузятся в этом сеансе: `$CLAUDE_CONFIG_DIR/CLAUDE.md` (если не задано — `~/.claude/CLAUDE.md`), а также `CLAUDE.md`, `.claude/CLAUDE.md`, `CLAUDE.local.md` на всех уровнях от текущей папки до корня. Управляемые блоки в файлах имеют приоритет:

| Ситуация | Поведение hook |
| --- | --- |
| Ни в одном из файлов нет блока `tavernweave-host-front-door` | Внедрить front door из плагина |
| Блок той же версии уже есть | Не внедрять, действует блок в файле |
| Блок другой версии | Не внедрять front door, только добавить замечание о несовпадении версий; блок в файле действует |
| Переменная `TAVERNWEAVE_FRONT_DOOR=off` | Не внедрять вообще |

- Пользователи, установившие плагин через маркетплейс, не должны записывать `CLAUDE.md` через `manage-host-front-door.ps1`. Если это уже сделано и вы хотите, чтобы плагин обновлял блок вместе с версией, выполните `manage-host-front-door.ps1 -AgentHost Claude -Action Remove` (сценарий сначала создаст резервную копию).
- Пользователи, установившие плагин из ZIP или копированием `skills/`, не получают этот hook и по-прежнему записывают `CLAUDE.md` описанным выше способом.
- Уровень поддержки (блок `tavernweave-guidance-preference`) не затрагивается и по-прежнему хранится отдельно в `CLAUDE.md`.

Статус проверки: структура hook, агента и переключателя Soul, правила устранения дублирования, формат вывода и согласованность инструкций проверяются офлайн в [`tests/claude-plugin.test.mjs`](tests/claude-plugin.test.mjs), поведение интерфейса Soul — в [`hooks/soul-switch.test.tsx`](hooks/soul-switch.test.tsx) для терминала и десктопа; фактическая инъекция в новом сеансе Claude Code, запуск через `--agent` и вызов субагента пока не проверены на реальных машинах (см. манифест установки `claudePlugin.hostLoading`).

## DeepSeek Harness

Начиная с 2.1.0 DSH устанавливается отдельным пакетом плагина, **не** копируйте `skills/` в `.agents/skills` и не пишите `AGENTS.md`:

1. Скачайте `TavernWeave-DSH-v2.4.0.tgz` со [страницы выпуска v2.4.0](https://github.com/LiarMTTT/TavernWeave/releases/tag/v2.4.0) или заново соберите локальный пакет командой `node scripts/build-dsh-plugin.mjs` в дереве исходников;
2. DSH Desktop: боковая панель **Плагины → Добавить плагин → Установить сторонний плагин → локальный путь/tarball**, после установки включите bundle;
3. Создайте новую задачу и выберите в presete агента **TavernWeave X DSH**.

Профили CLI/Web используют `dsh plugin --profile <profile> add <локальный путь|tarball|git-адрес|имя пакета>`; профиль `desktop` управляется оболочкой Desktop, не вызывайте CLI напрямую.

Пакет плагина сразу содержит 23 навыка и Host Front Door (внедряется как раздел system prompt); установка, обновление и удаление идут через механику плагинов DSH. Подробный состав, машинный контракт и ворота среды выполнения — в [host-adapters/dsh/README.md](host-adapters/dsh/README.md). DSH находится в Developer Preview. В 2.1.0 на DSH Desktop `0.2.1-rc.2` реально проверены страница плагина, выбор пресета, каталог из 23 навыков, Front Door, Soul и терминал с полными правами; качество модели, Linux/WSL и реальная таверна остаются отдельными пунктами проверки. Рабочие папки с reparse-point OneDrive при workspace-write требуют переключения в полные права или обычной папки (см. контракт `knownEnvironmentIssues`).
